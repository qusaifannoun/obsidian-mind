# Q3 2026

Running log of impact, growth, and collaboration for the quarter. Evidence links to work notes and competencies.

## Impact & Deliverables

- **Staff self-service polish — 8 QA-driven [[tat-prereq]] fixes across profile, Manage Staff, and Form 285 ([[tat-prereq]], 2026-07-08).** Shipped a batch of staff-management FE work in three commits (`c267616`, `4a17423`, `af17500`): a searchable **nationality dropdown** (`GET /country`, storing the country name for [[tat-ws]] parity on the shared user collection), **national-ID 10-digit** validation, **self-service change-password** wired to the existing `POST /auth/change-password` (zod mirroring the backend `IsStrongPassword` DTO, gated to `self` so admins don't see it on others), a **Form 285 title dropdown** and a **Manage Staff eye-icon** (QA: drop the row-click + kebab). Also root-caused three bugs by **verifying every endpoint shape with a live staging token** (offline fetchers hide contract drift): a **stale `profiles/me` mapper** silently dropping half the profile fields after the backend expanded the endpoint; the qualifications/assessments panels hammering **non-existent per-user routes (404 + retry storm)** — rewired to **aggregate the real per-TOR endpoints** across the member's TORs; and a **`STATUS[value].cls` crash** on an unmapped backend enum, hardened with a neutral fallback. Evidence: [[Staff Self-Service Polish - Nationality, Password, Profile Data]], [[Gotchas]].
- **Notification system — bell, real-time updates, and a cross-repo deep-link fix ([[tat-prereq]] + [[tat-app-ws Backend]], 2026-07-08).** Built the full notification layer for [[tat-prereq]] from zero: a navbar bell with an unread badge and a **Socket.IO-driven flashing dot** that fires on each pushed `notification` event, a `/notifications/[id]` detail page, and a React-Query API layer covering all **9 `/api/notifications/*` endpoints** — discovering along the way that the socket must connect to the API **origin**, not the `/api`-prefixed REST base (auth via the access token, room keyed on the user `_id`). On the backend, traced why staff-management notifications were silently resolving to the **admin dashboard** instead of tat-prereq (`resolveClientBaseUrl` only knew two frontends), added a third **env-driven client base URL** (`STAFF_MANAGEMENT_URL` → `staff.tat147.com`), and **repointed 21 notification settings (39 params)** to the correct tat-prereq routes — deep-linking Form 285/32 and assessments via `torId`, which the responses already carried through `toDTO` (no form-service changes needed). Chose a **non-destructive, idempotent migration** over bootstrap's destructive re-seed because the dev DB is shared. `nx run api:build` + tsc/eslint/next build clean on both repos; committed `d760e2b` (tat-prereq) and `07cd3fba` (tat-app-ws) to `dev`. Evidence: [[TAT Notification System - Bell, Detail Page & Prereq Deep-Links]], [[Patterns]], [[Gotchas]].
- **Six bugs root-caused and shipped in one session — Form 32 PIC saves + cross-frontend auth ([[tat-app-ws Backend]] + [[tat-prereq]] + [[tat-portal]], 2026-07-08).** Root-caused a subtle `Object.assign` clobber that wiped a Form 32's name/date/sections on **every** first-time PIC save — the merge helper returned the whole stale record, not just the merged piece, and the FE always sends a truthy `assessment: {}`, so it fired every time behind a misleading "sections incomplete" error. Cracked it on staging with **discriminating payloads that bisected which of four identical-error validations fired**, and by reproducing the class-validator transform locally to disprove a wrong hypothesis (`@IsOptional()` does not strip). Fixed alongside a sibling create-401 (PIC missing from the `SM_CREATE_FORM_32` seed bucket), a signature-draw reuse of the Form 285 component, and an auth bundle across all three repos: reset-password endpoint contract (`POST`→`PATCH /:token`), login length (`min(8)`→`min(1)`) that was blocking valid legacy/admin logins, a dead Email field, and the `x-client-app: staff-management` reset-link routing gap (each link resolver has its **own** branch list). Evidence: [[Form 32 PIC Bugs & Cross-Frontend Auth Fixes]], [[Gotchas]], [[Patterns]].
- **Built a complete reviewer worklist ("Pending Review Requests") + hardened the History Form ([[tat-app-ws Backend]] + [[tat-prereq]], 2026-07-09).** Turned the per-staff Pending TORs page into a **per-request worklist** that surfaces *every* reviewer-actionable pending item in the subsystem — Form 285, Form 32 A–D, Assessment, Aircraft Qualification, Initial TOR Documents, and all History-Form items (basic-info / mandatory training / training-history / sit-in / course request) — each deep-linking to its review page, with staff-name search, a kind filter (with `form_32`/`history` umbrellas), and server pagination. Required a new aggregate endpoint spanning **8 collections** + normalization, shipped in slices (`10c0d1cf`→`b520fd7d` backend, `fa8aed5`→`3728a08` FE) after establishing there was no per-review-request data before. Then fixed two History-Form bugs: **basic-info could only reject one field** (each reject flipped the whole form to REJECTED and its guard blocked the rest — added a plural reject endpoint + accumulate-and-send UX mirroring Form 32), and **built the Experience + Part 66 sections from stubs** into real approvable basic-info fields (chose the "same approval as basic info" model → reused the entire save/submit/approve/reject machinery with zero new endpoints). Evidence: [[Pending Review Requests - Reviewer Worklist]], [[Form 32 Rejection History & Round-Scoped Stamps]].
- **Form 32 rejection redesign + full review-history timeline, spec'd via a grill-me session and shipped across both repos ([[tat-app-ws Backend]] + [[tat-prereq]], 2026-07-09).** A BA-reported bug — Form 32 field rejections *accumulated* across review rounds (fix Section 1 → reject only Section 3 → owner still saw 2 rejected) — root-caused to per-field rejection stamps that were never reset. Ran a **`/grill-me` design session** to resolve the model one decision at a time (round-scoped stamps via **clear-on-submit**; a **unified `data.reviewHistory` event log** — rejected/edited/uploaded/approved, each with actor + timestamp; per-item **`History (N)`** timeline in the FE), then implemented backend-first and FE. Along the way: added a warning that **rejecting discards a reviewer's unsaved edits** (reject sends only field ids, not the form body), and caught **two reference bugs** — a Mongoose single-nested-subdocument spread that silently dropped every History-Form basic-info save (`7c359c08`), and a **shallow-copy mutation** that made the new before/after diff always empty so no edit/upload event was ever recorded (`8ad91259`, found by Qusai testing a document replacement). Commits `63bce30a`/`8ad91259` (backend), `fe78ce1`/`64ae543` (FE). Evidence: [[Form 32 Rejection History & Round-Scoped Stamps]], [[Gotchas]], [[Patterns]].
- **Root-caused why staff-management notification deep-links still pointed at the wrong host despite the env var, and redesigned the resolution ([[tat-app-ws Backend]], 2026-07-09).** After `STAFF_MANAGEMENT_URL` was set, staff notification links *still* resolved to the admin dashboard. Traced it to two compounding behaviors: the base URL was **baked into the stored setting at seed time**, and re-seeding **skips already-existing settings** — so the env var never took effect, and the send-time resolver was dead code (the stored URL was already absolute). Fixed it properly (**option A over a quick re-bake**): store the **relative** URL + client and resolve the base per-client at **send time**, plus a migration to relativize existing rows (ran on `dev`, 66/67), and deleted the superseded bake-absolute migration so it can't reintroduce the bug. Generalized the lesson into [[Patterns]] ("resolve env-dependent values at use time, never freeze them into a DB row") and [[Gotchas]]. Prevented broken deep-links reaching real staff. Evidence: [[TAT Notification System - Bell, Detail Page & Prereq Deep-Links]].
- **Assessment Report rubric (TAT-423) — modelled the entire graded form, then shipped it across both repos via parallel platform agents ([[tat-app-ws Backend]] + [[tat-prereq]], 2026-07-09).** Caught that the Assessment Form was implemented as only the assign→sign→approve **shell** — a box-by-box read of the real paper form (`TAT FORM 032.08.25`) against the data model showed the entire graded body was un-modelled (14 scored criteria across Knowledge/Skills/Competence, DSL/INSTR/EXAM/ASS discipline flags, objective pass, task/reference, overall rating, Part 147 compliance, assessor + TM comments). Designed the `report` data contract, **validated it against all 22 ACs** (catching two live divergences — AC-21 instructor-editable type, AC-16 no-edits-after-approved — and one status-model call, AC-11), then **fanned the build out to two platform agents in parallel** (backend schema/DTO/endpoint + frontend UI, integration deliberately gated until the backend shipped) to compress wall-clock. Backend adds a `report` subdocument, `PATCH .../assessments/:id/report`, a submit-time completeness gate, and TM comments; FE renders the full rubric read-only-once-approved and wires the save. Both `dev`; `api:build` + tsc/eslint clean. Separately fixed the `assessment_report` form template being CARC-only (raw-inserted in the DB, never seeded) → now per-license for all authorities. Evidence: [[TAT-423 Assessment Report Rubric]], [[Gotchas]].
- **Restructured staff-profile sections by data ownership + fixed the privileged qualification submit ([[tat-prereq]], 2026-07-09).** Moved Aircraft Qualifications + Assessments off the profile (they're per-license, not per-instructor) into the TOR detail, added read-only History-Form + Initial-Documents **mirrors** on each TOR (home stays on the profile), redesigned Related TORs (dropped the misleading TOR-level status + kebab, whole-row link), and fixed a privileged aircraft-qualification submit that 400'd because a privileged submit **auto-approves and requires a refresher date** the FE never collected. Evidence: [[Patterns#Staff subsystem section placement: per-instructor lives on the profile (+read-only TOR mirror), per-license lives in the TOR (2026-07-09)]].
- **Found a circular dependency that made new-instructor onboarding impossible, and traced it to two contradicting tickets nobody had read together ([[tat-app-ws Backend]] + [[tat-ws]], 2026-07-12).** A fresh instructor never appeared in **Add Instructor** on an aircraft-type course. The BA said TOR status shouldn't gate that list; verifying it in code turned up something stronger than a spec disagreement — a **closed loop across four services**: a TOR only activates once the History Form is approved, which requires the sit-in final assessment, which requires a sit-in — and `addCourseInstructor` (the repo's **only** `sitInModel.create`) demanded an Active TOR. *To get an Active TOR you needed a sit-in; to get a sit-in you needed an Active TOR.* Nobody could ever be onboarded, and the symptom was an **empty list**, which reads as "nobody qualifies" rather than "this gate cannot be passed". Root process cause: **TAT-424 and TAT-429 contradict** — 424's AC-09 swept "Course instructor assignment" into a global Active-TOR rule, over-reaching into 429's bootstrap path; each ticket carried a lone "Approved" comment 13 days apart. Fixed by implementing **TAT-429 AC-03 as written for the first time** (the deviation was what shipped), scoped so teaching/examining assignment keeps the 424 rule, and added **sit-in move semantics** (soft-delete + audit + evaluator notification, with a 409 guarding an already-submitted assessment, and teardown ordered *last* so a failure can't destroy the old sit-in). Also caught, pre-ship, that the new notification would have shipped **mute** — `bootstrap.service` silently skips any setting with no mapping entry, and `sendNotification` no-ops on a miss. Backend `9da69984`, FE `1862d90`. **Then drove the unblocked cycle end to end on staging — the first complete sit-in in the product's history** (instructor added → evaluator submitted → TM signed → History Form `APPROVED`), which promptly surfaced **four latent bugs** that had been unreachable behind the deadlock since TAT-421 shipped: a completed sit-in 404'ing and rendering as an empty section, the instructors list showing an approved instructor as "No sit-in", `SIT_IN_CREATED` **misattributing the audit trail to the instructor** instead of the SA who added them (an audit log that lies is worse than one that's missing), and an unlabelled event rendering as a raw enum. Root of two of them: `StaffSitIn.active` means *"in progress"* but three read paths used it as *"exists"* — **including one I had written myself hours earlier**, caught by grepping every use of the field after finally understanding its semantics rather than fixing only the reported instance. Also closed the visibility gap that made the feature unusable — adding an instructor produced *no feedback at all* — with a new list endpoint, a Trainees/Instructors tab split (AC-05 forbids mixing instructors *into* the trainee table, not showing them), sit-in status per row, and search + status filters. Backend `0bab2340`/`b5e0ddc1`/`5b60f193`/`0c1f1cbb`, FE `ecea1c3`/`1669a89`/`9cb360f`. Evidence: [[TAT-429 Sit-In Eligibility & Move Semantics]], [[Gotchas]].
- **Root-caused and fixed a bug blocking all staff creation on staging ([[tat-app-ws Backend]], 2026-07-07).** A Mongoose enum `Prop` with `default: null` on `User.qualificationTrackingMode` failed validation on **every** new document, breaking `POST /auth/internal-user/signup` for all roles via both [[tat-prereq]] and the live backoffice. Used the "two independent frontends fail identically" signal to rule out the frontend and localize to the backend schema, traced the field's actual domain semantics against three expiry crons before choosing the fix, and identified this as the **3rd/4th instance of a recurring `enum + default: null` anti-pattern** across the schema — flagging it for a lint/schema-review rather than a one-off patch. Fixed and pushed same-day (`dc8f3a4f`). Evidence: [[Staff Creation Blocked - qualificationTrackingMode Enum Bug]], [[Gotchas]].

## Technical Growth

- **Socket.IO consumption invariant** — a real-time client must connect to the API **origin**, not the `/api` REST prefix; auth rides on `handshake.auth.Authorization` (Bearer) and the server rooms by user `_id`. Now captured so the next real-time feature doesn't re-derive it. Evidence: [[Patterns]].
- **Multi-frontend notification routing** — modelled how one backend notification pipeline targets different apps via `resolveClientBaseUrl` + a per-setting `client` tag baked at seed time, and why already-seeded environments need a migration (bootstrap skips existing settings) rather than a reboot. Evidence: [[Patterns]].
