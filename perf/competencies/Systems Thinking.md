# Systems Thinking

## Definition

Holding the whole system in view — how repos, APIs, auth, and data models depend on each other — so a change in one place is made with awareness of its ripples, and so non-obvious domain distinctions (e.g. two separate certificate systems) are recognized rather than conflated.

## Proficiency Levels

| Level | Description |
|-------|-------------|
| Working | Understands the component being worked on |
| Strong | Understands adjacent services and shared contracts |
| Lead | Maps the whole system; documents the seams so others don't re-derive them |

## Growth Notes

Continue capturing cross-cutting contracts (auth, email links, shared models) as reference notes so the map outlives any one task.
